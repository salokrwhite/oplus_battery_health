# Oplus 设备电池健康读取模块

> 语言：[English](README.md) | 简体中文

一个用于 **Magisk / KernelSU / APatch** 的模块，在手机上直接读取并展示电池健康（诊断项 `030103`）结果。

模块的行为目标是与 OPPO 官方售后检测工具（O+ Support）保持一致：读取设备上已有的官方电池数据，按官方同样的判定方式给出等级，并在数据不可用时如实返回"不支持"，而不是自行猜测或用近似值替代。

> 结果具有较高的参考价值，但会受设备型号、系统版本与固件差异影响，**最终请以官方售后工具的检测结果为准**。

## 功能

* 读取电池健康百分比与等级（优 / 良 / 差），并给出与官方一致的等级区间说明
* 提供终端输出、WebUI 页面与"动作按钮"三种使用方式
* 可选显示附加信息（电量、电压、电流、温度、充电状态、循环次数），这些数据**不会**参与健康值判定
* 仅使用设备自身的官方数据源；数据缺失时明确提示"不支持"，无兼容兜底、无替代数据源

## 环境要求

* 已 root 的设备（Magisk v24+ / KernelSU / APatch）
* Android 10 及以上
* 支持 Shell 交互的环境（普通终端应用即可）

## 安装

在 Magisk / KernelSU / APatch 中刷入本模块 ZIP，重启设备。安装脚本会完成必要的检查与挂载工作。

## 使用方式

### 1. 命令行

```bash
su -c batteryhealth              # 人类可读输出
su -c "batteryhealth --kv"       # key=value 形式（供脚本调用）
su -c "batteryhealth --json"     # 单行 JSON 形式
su -c "batteryhealth --kv --extra"  # 追加附加信息
```

### 2. WebUI

* **KernelSU / APatch**：打开模块，点击 *WebUI*。
* **Magisk**：Magisk 自带页面没有 WebUI 宿主，模块会在开机时启动自带的本地 HTTP 服务（纯内置实现，不依赖 busybox），监听 `127.0.0.1:8899`，用浏览器打开 `http://127.0.0.1:8899/` 即可。

  如需关闭该服务：

  ```bash
  su -c "touch /data/adb/modules/oppo_battery_health/disable_http"
  ```

  也可以自行使用 KsuWebUIStandalone、MMRL 等第三方宿主。

### 3. 动作按钮

模块自带 `action.sh`，因此在 Magisk / KernelSU / APatch 中会显示"动作"按钮。点击后会自动打开模块页面；页面本身在点击"读取电池健康"时才真正读取数据。

> 动作按钮需要屏幕处于点亮状态，熄屏时无法把浏览器切到前台；使用动作按钮时这一点自然满足。

## 输出示例

```
电池健康 (030103)
  percent      = 76.65 %
  level        = 良
  legend       = 优：80-100%，良：60-80%，差：0-60%
  status       = normal

  fcc          = 3550 mAh
  design       = 4510 mAh
  判级与记录（等级用未舍入值判定）:
    ratio_exact= 76.651884700699995
    record_int = 76
```

字段说明：

| 字段 | 含义 |
|---|---|
| `percent` | 电池健康百分比（两位小数，仅用于展示） |
| `level` | 等级：优 / 良 / 差，与官方判定一致 |
| `legend` | 各等级对应的百分比区间说明 |
| `status` | 判定状态，见下表 |
| `fcc` | 当前满充容量 |
| `design` | 出厂标称容量 |
| `ratio_exact` | 参与判定的精确比例值（未舍入） |
| `record_int` | 与官方记录一致取整后的数值 |

判定状态：

| status | 含义 |
|---|---|
| `normal` | 数据正常，等级为优或良 |
| `abnormal` | 健康值低于官方阈值下限，等级为差 |
| `unsupported` | 所需数据在当前设备/固件上不可用 |

因为等级是按未舍入的数值判定的，所以像 `59.999 %` 这样显示为 `60.00 %` 的结果，其等级仍为"差"——这与官方工具的表现一致。

## 设计原则

* **只认官方数据源。** 使用的全部是设备自身固件里已有的电池信息，不使用任何第三方数据库或估算模型。
* **不做兼容兜底。** 官方判定所需的某项数据缺失时，模块直接返回"不支持"，而不是退回到一个来源不明的结果。
* **区分展示与判定。** 页面上的两位小数只是显示格式，判定始终使用精确值，避免出现"四舍五入跨过阈值"导致的等级偏差。
* **附加信息不参与判定。** 电压、电流、温度、循环次数等只作为参考单独展示。

## 副作用与隐私

* 模块**只输出结果，不写任何文件**，不生成结果文件、不修改系统配置。
* **不发通知**（早期版本的通知功能因多数系统会静默丢弃 shell 提交的通知而移除）。
* 不联网上报任何数据：读取完全在设备本地完成，WebUI 服务也只监听本机回环地址。
* 模块在开机时会启动一个仅监听 `127.0.0.1` 的本地页面服务，可通过上面的 `disable_http` 方式关闭。

## 已知限制

* 电池健康数据依赖设备固件本身提供，在部分机型或部分系统版本上会返回"不支持"，属于正常现象。
* 官方售后工具自身在不同系统版本上的实现也有所差异，本模块以相同口径读取同一批物理量，最终数值在两种渠道下应当一致。
* 等级区间来自官方当前的配置数据，属于当前版本的快照；官方后续若调整配置，本模块不会自动跟随更新。
* 电池健康（`030103`）之外的诊断项（如屏幕相关项、蓝牙耳机相关项）不在本模块范围内。
